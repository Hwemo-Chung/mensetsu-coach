# 설계서 B — 국제우편 단순처리 에이전트

Built with Claude: Japan 2026 제출 후보 B. 작성 2026-10-28. 최종 제출작 결정은 선발 결과(10/30) 후.

## 1. 한 줄 소개
해외 거주자가 국제우편으로 받는 서류·소포를 사진 한 장으로 "무엇인지, 언제까지, 뭘 해야 하는지"까지 정리해 주고, 보낼 때는 세관신고서 작성까지 도와주는 에이전트.

## 2. 페르소나와 문제
- 페르소나: 일본 거주 외국인 (가족·관공서·금융기관과 모국 간 우편 왕래가 잦음)
- 문제: 국제우편은 ① 뭐가 온 건지 모국어로 바로 파악이 안 되고 ② 세관 과세 통지·부재표·재배달 같은 일본 우편 절차가 낯설고 ③ 기한을 놓치면 반송·추가 비용이 생김. 보낼 때는 세관신고서(CN22/CN23) 항목 작성이 번번이 헷갈림
- 주최 테마 정합: 언어·기술 장벽 제거, 일상 불편 해결. 대상은 전 세계 해외 거주자로 확장 가능

## 3. 핵심 기능 (MVP는 수신 처리에 집중)
### 수신 처리
1. **판별**: 우편물/동봉 서류 사진 업로드 → 발신 기관, 문서 종류 판별 (예: 税関からの課税通知書, 不在連絡票, 관공서 안내문, 금융기관 서류)
2. **요약**: 원문 핵심을 모국어(한국어 등)로 쉬운 요약 + 금액·기한 등 숫자 항목을 표로 추출
3. **행동 체크리스트**: 해야 할 일을 순서대로 제시 (예: 세금 납부 방법·장소, 재배달 신청 경로, 회신 필요 여부와 기한). 기한이 있으면 D-day로 강조
4. **분류·보관**: 중요도(긴급/일반/보관)를 붙여 목록화

### 발송 처리 (확장)
5. **세관신고서 보조**: 내용품·수량·중량·가격을 대화로 입력하면 CN22/CN23 항목을 채워 미리보기 생성, HS코드 후보 제안
6. **규정 체크**: 국가별 금지·제한 품목 경고, 발송 방법(EMS/국제소포/서장) 비교 안내

## 4. 처리 흐름
사진 업로드 → Claude 비전 판독 (종류/발신/기한/금액 추출) → 신뢰도 낮은 항목은 "확인 필요"로 표시 → 요약 카드 + 체크리스트 생성 → 사용자가 완료 체크하면 보관함으로 이동

## 5. 기술 구성
- 개발: Claude Code. 실행: Claude API (비전 + 텍스트)
- 프론트: 모바일 우선 웹앱 (사진 촬영·업로드가 핵심 동선). 결과는 카드형 UI
- 데이터: 우편물 레코드 JSON (종류, 발신, 기한, 금액, 체크리스트, 상태). 원본 사진은 처리 후 삭제 옵션 제공 (개인정보 배려를 심사 포인트로)
- 프롬프트 구조: 문서 종류별 판별 가이드 + 추출 스키마 고정 + 불확실하면 추측 금지·확인 표시 규칙
- 일본 우편 절차 지식 베이스: 과세 통지 납부, 재배달 신청, 보관 기한 등 절차를 작은 규칙 문서로 분리해 주입

## 6. 개발 일정 (11/2~11/10, 솔로 기준)
- 11/2: 킥오프 확인, 설계 동결, 골격·비전 판독 연결
- 11/3~4: 판별·추출 스키마 + 요약 카드 (수신 핵심 루프)
- 11/5~6: 절차 지식 베이스 + 행동 체크리스트 생성
- 11/7: 분류·보관 목록, 기한 D-day 표시
- 11/8: 실제 우편물 샘플(과세 통지, 부재표 등)로 정확도 테스트
- 11/9: 데모 시나리오·소개 문구 마감 (발송 보조는 여유 시)
- 11/10: 제출 (14:00 마감, 오전 중 제출 목표)

## 7. 심사 어필 포인트
- 해외 거주자라면 누구나 겪는 반복 불편 + 기한 리스크라는 명확한 문제
- "번역"이 아니라 "판별 → 기한 → 행동"까지 끝내는 에이전트형 설계
- 일본의 외국인 거주자 증가와 우편·행정 절차의 디지털 격차라는 사회 맥락

## 8. 리스크와 대안
- 판독 정확도: 숫자(금액·기한) 오인식 위험 → 원본 대조 표시와 "확인 필요" 플래그로 완화, 데모는 판독이 안정적인 문서 종류부터
- 절차 안내의 정확성: 국가·기관별 절차 차이 → MVP는 일본 거주 수신 케이스로 범위 고정
