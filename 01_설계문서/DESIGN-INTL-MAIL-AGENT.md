# 設計書B — 国際郵便シンプル処理エージェント

Built with Claude: Japan 2026 提出候補B。作成 2026-10-28。最終提出作の決定は選考結果（10/30）の後。

## 1. 一言紹介
海外在住者が国際郵便で受け取る書類・小包を、写真1枚で「何なのか、いつまでに、何をすべきか」まで整理し、送るときは税関告知書の作成まで手伝うエージェント。

## 2. ペルソナと課題
- ペルソナ: 日本在住の外国人（家族・官公庁・金融機関と母国との間で郵便のやり取りが多い）
- 課題: 国際郵便は ① 何が届いたのか母国語ですぐに把握できず ② 税関の課税通知・不在票・再配達といった日本の郵便手続きに馴染みがなく ③ 期限を逃すと返送・追加費用が発生する。送るときは税関告知書（CN22/CN23）の項目記入で毎回迷う
- 主催テーマとの整合: 言語・技術の壁の解消、日常の不便の解決。対象は世界中の海外在住者に拡張可能

## 3. 中核機能（MVPは受け取り処理に集中）
### 受け取り処理
1. **判別**: 郵便物/同封書類の写真をアップロード → 差出機関、文書の種類を判別（例: 税関からの課税通知書、不在連絡票、官公庁の案内文、金融機関の書類）
2. **要約**: 原文の要点を母国語（韓国語など）でわかりやすく要約 + 金額・期限などの数値項目を表に抽出
3. **行動チェックリスト**: やるべきことを順番に提示（例: 税金の納付方法・場所、再配達の申込経路、返信の要否と期限）。期限があれば D-day として強調
4. **分類・保管**: 重要度（緊急/一般/保管）を付けて一覧化

### 発送処理（拡張）
5. **税関告知書の補助**: 内容品・数量・重量・価格を対話で入力すると CN22/CN23 の項目を埋めてプレビューを生成、HSコードの候補を提案
6. **規定チェック**: 国別の禁止・制限品目の警告、発送方法（EMS/国際小包/書状）の比較案内

## 4. 処理フロー
写真のアップロード → Claude ビジョンで読み取り（種類/差出/期限/金額の抽出）→ 信頼度の低い項目は「要確認」と表示 → 要約カード + チェックリストの生成 → ユーザーが完了をチェックすると保管箱へ移動

## 5. 技術構成
- 開発: Claude Code。実行: Claude API（ビジョン + テキスト）
- フロント: モバイルファーストの Web アプリ（写真の撮影・アップロードが中心の動線）。結果はカード型UI
- データ: 郵便物レコード JSON（種類、差出、期限、金額、チェックリスト、状態）。元の写真は処理後に削除するオプションを提供（個人情報への配慮を審査ポイントに）
- プロンプト構成: 文書の種類別の判別ガイド + 抽出スキーマの固定 + 不確かなら推測禁止・確認表示のルール
- 日本の郵便手続きのナレッジベース: 課税通知の納付、再配達の申込、保管期限などの手続きを小さなルール文書に分離して注入

## 7. 審査でのアピールポイント
- 海外在住者なら誰もが経験する繰り返しの不便 + 期限のリスクという明確な課題
- 「翻訳」ではなく「判別 → 期限 → 行動」まで完結するエージェント型の設計
- 日本の外国人居住者の増加と、郵便・行政手続きのデジタル格差という社会的文脈

## 8. リスクと代替案
- 読み取り精度: 数字（金額・期限）の誤認識のリスク → 原本との照合表示と「要確認」フラグで緩和、デモは読み取りが安定した文書の種類から
- 手続き案内の正確性: 国・機関別の手続きの違い → MVPは日本在住の受け取りケースに範囲を固定
