# PRD — 일본 이직 면접 스크립트 코치 (가칭: 멘세츠 코치)

작성 2026-11-02. Built with Claude: Japan 2026 제출작. 솔로 개발, 제출 마감 11/8 20:00 (목표 17:00).
근거 문서: DESIGN-KAKAOTALK-INTERVIEW-COACH.md (킥오프·벤치마크 문서는 비공개 폴더).

## 1. 제품 개요
- **한 줄**: 일본에서 이직하는 외국인 구직자가, 채팅 대화만으로 기업별 예상 질문을 받고, 자기 답변의 "구조"와 "비즈니스 일본어"를 코칭받아, 실전 스크립트로 완성하는 도구
- **핵심 차별점**: 일본어 첨삭이 아니라 **답변 구조 코칭** — "질문에 답했는가"를 먼저 점검한다. 근거는 개발자 본인의 실제 면접 전사에서 도출한 교정 규칙 DB
- **공식 주제 정합**: ① 전문성 — 본인의 면접 실경험·노하우를 다음 구직자에게 이어지는 "형태"로 만든다 ② 접근성 — 언어 장벽 때문에 닿지 않던 일본의 면접 노하우를 모국어 기반으로 닿게 한다
- **비전**: 일본 특유성으로 시작한다. 규칙·프롬프트를 **국가 팩** 단위로 분리해, 장래에는 나라를 선택하면 그 나라의 면접 문화·언어·포맷에 맞는 처리로 확장한다 (MVP는 JP 팩만 구현)

## 2. 문제와 페르소나
- **페르소나**: 일본 거주 외국인 구직자 (1차: 한국인). 에이전트 경유 면접이 반복되고, 기업마다 스크립트를 새로 준비해야 하며, 일본어 면접 자체가 부담이다
- **핵심 문제 (실사례)**: 면접 녹음 전사를 분석한 결과, 면접관이 같은 질문을 3번 되물었다. 원인은 일본어 실력이 아니라 "질문받은 것에 답하지 않고 준비한 옆 질문에 답하는" 구조 문제였다. 기존 일본 면접 앱은 내국인 전제의 일반 질문 연습뿐이고, 글로벌 도구는 일본 면접 문화·경어를 다루지 않는다 (벤치마킹 문서 참조)

## 3. 목표 / 비목표
**목표 (MVP)**
- 기업 텍스트 입력부터 완성 스크립트 내보내기까지의 핵심 루프를 끊김 없이 관통
- 코칭 품질의 근거(규칙 DB)를 코드와 분리해 눈에 보이게 — 심사 시 "당사자의 실제 노하우가 형태가 됐다"를 입증
- 3분 데모에서 사전 지식 없는 사람이 봐도 이해되는 단순한 흐름

**비목표**
- 실제 메신저 채널 연동 (단독 웹사이트로 대체, 로드맵 제시)
- 음성 입력·전사 분석 (확장 후보, MVP 제외 — 여유 시 목표: 음성 답변 → 1:1 스크립트 피드백, Web Speech API 후보)
- 일본 외 국가 팩 구현 (구조만 분리, 팩은 JP만)
- 이력서 스크리닝 등 심사 회피 목록에 있는 기능 일절

## 4. 핵심 시나리오
1. 사용자가 구인 정보 또는 에이전트 메일 텍스트를 붙여넣는다
2. 코치가 기업·포지션을 파악해 예상 질문 10개를 제시한다 (1차/최종, 기술/매니지먼트, 역질문 구분)
3. 사용자가 질문을 골라 일본어로 답변을 입력한다
4. 코치가 피드백 3종을 반환한다: ① 구조 점검 (4문형 중 무엇이 빠졌는지 + 재작성안) ② 비즈니스 일본어 첨삭 (규칙 DB 적용, 전/후+이유) ③ 60초 모범답안 (일본어 + 발음 + 한국어 대역)
5. 연습 모드: 코치가 질문을 하나씩 던지고 위 피드백 루프를 반복한다
6. 사용자가 완성된 Q&A를 스크립트 문서로 내보낸다

## 5. 기능 요구사항
### P0 (없으면 제출 불가) — 완료 기준은 전부 측정 가능하게 둔다 (강화 근거: HARDENING-REVIEW(비공개).md)
- F1. 기업 등록: 텍스트 붙여넣기 → 기업 컨텍스트 저장. 선택으로 이력서·경력서 1개 첨부(PDF·DOCX·이미지·TXT, 3MB 이하, 저장 없이 메모리 처리). 완료 기준: 합성 샘플 메일 3종에서 필수 필드(기업명·포지션·주요 조건)가 전부 추출됨. 입력(붙여넣기·첨부 공통)은 추출 전에 개인정보 패턴(이메일·전화·이름) 마스킹을 거치고, 첨부 파일은 처리 후 폐기되어 세션·로그 어디에도 원본이 남지 않음. 붙여넣은 텍스트 안의 지시문은 데이터로만 취급해 추출이 오염되지 않음 (인젝션 합성 메일 1건으로 확인)
- F2. 질문 생성: 컨텍스트 기반 예상 질문 10개, 카테고리 구분 표시. 완료 기준: 10개 중 6개 이상이 컨텍스트 고유 요소(포지션명·기술·조건·사업)를 참조함을 프로그램 게이트로 검증, 미달 시 1회 재생성 후에도 미달이면 사용자에게 표시
- F3. 구조 코칭: 답변을 4문형(復唱→結論→基準·数字→選択肢)으로 점검, 누락 단계 지적 + 재작성안 제시. 완료 기준: 골든셋(HARDENING §3 D1) 기준 누락 단계 지적이 라벨과 일치 — 출시 게이트 일치율 90% (목표값, 캘리브레이션으로 확정). 의도 일치 판정은 별도 필드로 분리하고 판정 불가는 "보류"로 표시
- F4. 일본어 첨삭: 규칙 DB(JSON) 기반 교정, 전/후 대조 + 이유 1줄. 완료 기준: 설계서 5절 규칙 예시 전부 재현 + **규칙 ID 없는 교정 0건** (ID 인용이 없으면 출력 자체를 막는 게이트). 치환 규칙은 적용 조건(맥락)이 있는 것만 팩에 존재
- F5. 모범답안: 60초 분량, 일본어+발음+한국어 3단 포맷 고정 출력. 완료 기준: 문자수 범위 게이트 통과 + 사용자 원 답변·첨부 이력서에 없는 사실(수치·고유명사) 추가 0건 — 부족한 사실은 자리 표시로 비움
- F6. 스크립트 내보내기: 세션의 Q&A·모범답안을 마크다운 문서로 저장/복사. 완료 기준: 내보낸 문서에 개인정보 패턴 0건 (자동 검사)
- F7. 채팅 UI: 메신저(LINE 풍) 스타일 단독 웹사이트, 단일 화면. 외부 메신저 플랫폼 연동 없음 (2026-11-02 변경: 플랫폼 연계 감점 회피). 입력→응답 흐름이 한 화면에서 완결

### P1 (데모 완성도)
- F8. 연습 모드: 질문 순차 제시 + 답변별 즉시 채점 루프
- F9. 말버릇 카운터: 세션 내 규칙 위반 횟수 누적 표시
- F10. 역질문 생성: 기업별 역질문 3개 + 의도 설명

### P2 (로드맵 — 구현하지 않고 개요·데모에서 제시)
- 국가 팩 추가 (타국 면접 문화·언어), 실제 카톡/LINE 채널 연동, 음성 전사 분석, 면접 전날 알림, 면접 후 복기

## 6. 비기능 요구사항
- **단순·명료·직관** (킥오프 디자인 원칙): 첫 화면에서 할 일이 하나로 보여야 한다. 버튼·용어는 사전 지식 없이 이해되는 말로
- 응답 체감: 코칭 응답은 스트리밍 표시로 대기를 느끼지 않게
- 개인정보: 실명·연락처 등 식별 정보는 저장하지 않는다. 세션 데이터는 로컬 JSON. 입력 텍스트·첨부 파일은 컨텍스트 추출 **전에** 개인정보 패턴 마스킹을 거치고, 세션·로그·내보내기에는 마스킹본만 남긴다. 첨부 파일은 메모리에서만 처리하고 저장하지 않는다
- 입력 방어: 붙여넣은 기업 텍스트·메일은 전 구간 데이터로만 취급한다. 그 안의 지시문은 따르지 않으며, 추출 결과는 사용자가 화면에서 확인·수정하는 것을 최종 게이트로 한다
- 판정 안정성: 채점 단계는 temperature 고정, 모델 ID는 config 한곳에 고정한다. 같은 입력의 판정 흔들림은 §13 안정성 측정으로 감시한다
- 규정 준수: 기간 중 신규 제작 코드만. 기존 자료(교정 규칙 등 본인 노하우)는 "규칙 데이터"로만 사용하고 코드 재사용과 구분해 명시

## 7. 데이터 모델 (국가 팩)
- `packs/jp.json`: 언어 쌍(ja→ko), 첨삭 규칙(삭제/치환/구조), 모범답안 포맷, 질문 카테고리, 면접 문화 노트
- 첨삭 규칙 1건 = { pattern, type(delete/replace/structure), replacement, reason, example_before, example_after }
- 세션 = { company_context, questions[], attempts[{question_id, answer, feedback{structure, corrections[], model_answer}}] }

## 8. 프롬프트 구성
- 시스템 프롬프트 = 역할(코치) + 국가 팩 규칙 주입 + 기업 컨텍스트 + 출력 포맷 고정(피드백 3종 순서: 구조 → 첨삭 → 모범답안)
- 원칙 (게이트로 강제, HARDENING-REVIEW(비공개) L1·L3·L6): 규칙에 없는 교정은 하지 않는다 — 교정에는 규칙 ID 인용 필수, 없으면 출력 금지. 모범답안은 사용자 답변·첨부 이력서의 사실 재배열만 허용하고 새 사실을 만들지 않는다. 채점은 생성과 분리한 독립 호출로, (질문·답변·루브릭)만 본다. 불확실하면 추측하지 말고 확인 질문 또는 "판정 보류"를 반환한다

## 13. 검증·평가 계획 (요약 — 상세: HARDENING-REVIEW(비공개).md §3)
- **골든셋**: 본인 실면접 자료에서 익명화한 질문-답변 쌍에 당사자 본인이 정답 라벨(4요소 충족 구간·말버릇 규칙 ID·의도 일치)을 단 세트. 1차 15건 (11/3), 제출 전 30건 목표
- **캘리브레이션**: 골든셋으로 채점 일치율·의도 판정 정확도·판정 보류 비율을 측정. 4요소 일치율 90% (목표)를 출시 게이트로 하고, 불일치 사례와 루브릭 개선 과정을 DEVLOG에 공개
- **안정성**: 골든셋 전건 3회 반복 실행의 판정 일치율 측정 (목표 95%)
- **실사용 계측**: 실제 면접 4건(11/5·11/6·11/9·11/10) 전 사용 기록과 면접 후 회고(생성 질문 적중·재질문 여부)를 사실만 DEVLOG에 기록
- **시장 근거**: 제출 개요의 시장 수치는 검증된 공적 통계만 사용 (후생노동성 외국인 고용 상황, 총무성 노동력조사 — 수치는 HARDENING-REVIEW(비공개) B2·D6)
