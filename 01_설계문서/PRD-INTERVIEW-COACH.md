## 1. 제품 개요

- **한 줄**: 일본에서 이직하는 외국인 구직자가, 채팅으로 기업별 예상 질문을 받고, 자기 답변에 맞는 일본어 비즈니스 스크립트(일본어·발음·번역)를 받아 실전 스크립트를 완성하는 도구.
- **핵심 차별점**: 일본어를 고쳐 주는 데서 끝나지 않고 **질문에 답하는 구조**를 먼저 잡습니다. 교정 규칙은 개발자 본인의 면접 기록에서 가져온 데이터이며 코드와 분리된 국가 팩(`packs/jp.json`)에 있습니다.
- **비전**: 일본에서 시작해 국가 팩을 추가하는 구조로 넓힙니다. MVP는 일본 팩 하나만 구현합니다.

## 2. 문제와 페르소나

- **페르소나**: 일본에 거주하는 외국인 구직자 (1차 대상: 한국어 사용자). 에이전트를 거친 면접이 반복되고, 회사마다 스크립트를 새로 준비해야 하며, 일본어 면접 자체가 부담입니다.
- **실사례**: 면접 녹음 전사를 보니 면접관이 같은 질문을 3번 되물었습니다. 원인은 일본어 실력보다, 질문에 답하지 않고 준비한 옆 질문에 답한 데 있었습니다.

## 3. 목표 / 비목표

**목표 (MVP)**
- 기업 자료 입력부터 질문 선택, 답변 입력, 스크립트 출력까지 끊김 없이 연결
- 출력이 일본어 필드에서 한국어로 바뀌지 않도록 프로그램 게이트로 강제
- 발음 표기로 억양과 강조를 한눈에 알 수 있게 함

**비목표**
- 메신저 플랫폼 연동 (단독 웹사이트로 대체)
- 음성 입력과 음성 분석 (확장 후보)
- 일본 외 국가 팩 구현 (구조만 분리)
- 이력서 스크리닝 등 심사 회피 목록에 있는 기능

## 4. 핵심 시나리오 (구현 기준)

1. 기업 메일이나 구인 정보를 붙여넣는다. 이력서·경력서는 선택 첨부.
2. 예상 질문 10개를 받는다 (일본어 질문, 한국어 번역, 근거 한 줄).
3. 번호를 입력해 질문을 고르고, 내 답변을 한국어나 일본어로 적는다.
4. 스크립트를 받는다: 일본어 경어 모범답안 / 발음(억양 표기) / 한국어 번역 / 억양·강조 포인트.
5. 다른 번호를 고르거나 새 메일을 붙여넣는다.

구조 점검(F3)과 첨삭(F4)은 다음 단계입니다.

## 5. 기능 요구사항

### F1. 기업 등록
- 텍스트 붙여넣기 또는 첨부 1개 (PDF, DOCX, 이미지, TXT/MD, 3MB 이하). 첨부는 저장하지 않고 메모리에서만 처리.
- 완료 기준 (미달): 입력 단계 개인정보 마스킹, 인젝션 합성 메일 테스트.

### F2. 질문 생성
- 질문 10개, 면접 단계와 카테고리 표시, 근거 한 줄.
- **일본어 필드 규칙**: `question_ja`는 일본어만. 한글이 섞이면 1회 재생성, 그래도 실패하면 오류 응답 (한국어가 일본어 질문으로 나오지 않게 하는 게이트).
- 완료 기준 (미달): 10개 중 6개 이상이 자료의 고유 요소를 참조하는지 검사.

### F5. 모범 스크립트
- 출력 항목 4개 고정: `ja`, `reading`, `ko`, `points`.
  - `ja`: 일본어 비즈니스 경어. 약 60초 분량. 결론을 먼저, 근거 숫자는 하나, 마지막은 상대에게 선택지로 넘김. 회답에 없는 수치·경력·고유명사는 만들지 않고 `［ここに実績の数字］`처럼 자리표시로 비움.
  - `reading`: `ja`의 발음을 한글로 적되 억양과 강조를 기호로 표시.
    - `↗` 올려 말하기
    - `↘` 내려 말하기
    - `《 》` 힘주어 말하기
    - `/` 짧게 끊기
  - `ko`: 한국어 번역.
  - `points`: 한국어로 된 억양·강조 포인트 2~4개.
- **언어 게이트**: `ja`에는 한글이 없어야 하고, `reading`과 `ko`에는 한글이 있어야 함. 실패하면 1회 재시도 후 오류.
- 완료 기준 (미달): 실호출 샘플 1건에서 4개 항목 모두 존재하고 게이트를 통과. 프롬프트를 바꾼 뒤 1회 확인 필요.

### F7. 채팅 UI
- 단계: 접근 코드 → 메일 → 질문 선택(번호) → 답변 → 스크립트 → 질문 선택으로 복귀.
- 입력창은 여러 줄이며 Enter는 줄바꿈입니다. Ctrl/Cmd+Enter로 전송합니다.

### F11. 접근 코드
- 코드 입력 단계에서 서버가 확인합니다. 맞을 때만 다음 단계로 넘어갑니다.
- 페이지를 열 때마다 코드를 다시 묻습니다.
- 운영 값은 배포 환경 변수에 있으며, 문서와 저장소에는 값을 쓰지 않습니다.

### F12. 화면 언어 (구현)
- 한국어, 일본어, 영어 중에서 선택합니다. 기본값은 브라우저 언어이며, 선택한 언어는 기억합니다.
- 화면 문구, 오류 문구, 면접 단계와 카테고리 표시를 모두 번역합니다.
- 서버는 오류를 문장이 아닌 코드로 반환합니다. 화면이 코드를 선택한 언어로 바꿉니다.
- 설명 언어(번역, 근거, 포인트)는 선택한 언어를 따릅니다.
- 언어 추가 방법: 번역 파일 1개 추가와 등록 1줄.
- 결정 (11/02): 발음 표기는 언어별. 한국어=한글, English=로마자(ヘボン式), 日本語=ひらがな. 억양 기호 ↗↘《》/는 공통.

## 6. 비기능 요구사항

- **개인정보**
  - 원문 메일과 첨부는 저장하지 않습니다. 브라우저에는 회사 요약과 질문만 남깁니다.
  - 서버 로그에는 원문과 첨부 내용을 남기지 않습니다.
  - 입력 단계 마스킹은 미구현입니다 (F1 참조).
  - Anthropic API의 데이터 보존 설정은 아직 확인하지 않았습니다.
- **입력 방어**: 자료나 답변 안의 지시문은 따르지 않습니다 (프롬프트 규칙). 인젝션 테스트는 미수행입니다.
- **접근 제어**: 코드가 설정되지 않으면 모든 요청을 막습니다. 요청 제한은 IP당 10분 10회이며, 서버 인스턴스 메모리에 있어 인스턴스 간에 공유되지 않습니다.
- **비용**: 토큰 사용량은 실측하지 않았습니다. 테스트는 기본적으로 가짜 클라이언트를 쓰고, 실호출은 프롬프트나 모델을 바꾼 뒤 1회만 합니다.
