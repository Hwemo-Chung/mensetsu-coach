## 1. 제품 개요

- **한 줄**: 일본에서 이직하는 외국인 구직자가, 채팅으로 기업별 예상 질문을 받고, 자기 답변에 맞는 일본어 비즈니스 스크립트(일본어·발음·번역)를 받아 실전 스크립트를 완성하는 도구.
- **핵심 차별점**: 일본어를 고쳐 주는 데서 끝나지 않고 **질문에 답하는 구조**를 먼저 잡습니다. 교정 규칙은 개발자 본인의 면접 기록에서 가져온 데이터이며 코드와 분리된 국가 팩(`packs/jp.json`)에 있습니다.
- **비전**: 일본에서 시작해 국가 팩을 추가하는 구조로 넓힙니다. 지금 구현된 것은 일본 팩 하나입니다.

## 2. 문제와 페르소나

- **페르소나**: 일본에 거주하는 외국인 구직자 (1차 대상: 한국어 사용자). 에이전트를 거친 면접이 반복되고, 회사마다 스크립트를 새로 준비해야 하며, 일본어 면접 자체가 부담입니다.
- **실사례**: 면접 녹음 전사를 보니 면접관이 같은 질문을 3번 되물었습니다. 원인은 일본어 실력보다, 질문에 답하지 않고 준비한 옆 질문에 답한 데 있었습니다.

## 4. 핵심 시나리오 (구현 기준)

1. 기업 메일이나 구인 정보를 붙여넣는다. 이력서·경력서는 선택 첨부.
2. 예상 질문 10개를 받는다 (일본어 질문, 설명 언어 번역, 근거 한 줄).
3. 번호를 입력해 질문을 고르고, 내 답변을 설명 언어나 일본어로 적는다.
4. 점검·첨삭을 받는다: 질문에 답했는가, 4단계(復唱→結論→基準・数字→締め) ✓/✗(復唱은 권장이라 없으면 팁), 규칙 DB 첨삭(before/after·이유).
5. 스크립트를 받는다: 일본어 경어 모범답안 / 발음(억양 표기) / 번역 / 억양·강조 포인트.
6. 다른 번호를 고르거나, 같은 질문에 다시 답하거나, 역질문을 받거나, "끝내기·저장"으로 마크다운을 내려받는다.

## 5. 기능 요구사항

### F1. 기업 등록
- 텍스트 붙여넣기 또는 첨부 1개 (PDF, DOCX, 이미지, TXT/MD, 3MB 이하). 첨부는 저장하지 않고 메모리에서만 처리.
- 완료 기준 (충족): 입력 단계 개인정보 마스킹(테스트), 인젝션 합성 메일 평가에서 지시 추종 0/10.

### F2. 질문 생성
- 질문 10개, 면접 단계와 카테고리 표시, 근거 한 줄.
- **일본어 필드 규칙**: `question_ja`는 일본어만. 다른 언어가 섞이면 1회 재생성, 그래도 실패하면 오류 응답.
- 완료 기준 (충족): 10개 중 6개 이상이 자료의 고유 어구를 참조하는지 코드로 검사(F2 게이트).

### F5. 모범 스크립트
- 출력 항목 최대 4개: `ja`, `reading`, `translation`, `points` (목적지 언어 = 모국어이면 `reading`·`translation` 없음, 11/03).
  - `ja`: 일본어 비즈니스 경어. 약 60초 분량. 결론을 먼저, 근거 숫자는 하나, 마지막은 상대에게 선택지로 넘김. 회답에 없는 수치·경력·고유명사는 만들지 않고 `［ここに実績の数字］`처럼 자리표시로 비움.
  - `reading`: `ja`의 발음을 모국어의 문자로 적되 억양과 강조를 기호로 표시 (표기는 아래 "언어 규칙 (2축)"). 목적지 언어 = 모국어이면 `reading`·`translation`을 요청하지 않고 보여 주지 않음 (11/03, 구현됨).
    - `↗` 올려 말하기
    - `↘` 내려 말하기
    - `《 》` 힘주어 말하기
    - `/` 짧게 끊기
  - `translation`: 설명 언어 번역.
  - `points`: 설명 언어로 된 억양·강조 포인트 2~4개.
- **언어 게이트**: `ja`는 일본어만, `reading`·`translation`·`points`는 설명 언어 게이트(`EXPLAIN_LANGS`)를 통과해야 함. 실패하면 1회 재시도 후 오류.
- 완료 기준 (충족, 11/02): 실호출 ko·en·ja 각 1건에서 4개 항목 존재·게이트 통과. 프롬프트를 바꾸면 다시 1회 확인. → 11/03 프롬프트 변경(히라가나 발음, 번역만 재요청) 후 재확인 필요.

### F7. 채팅 UI
- 단계: 접근 코드 → 메일 → 질문 선택(번호) → 답변 → 점검·첨삭 + 스크립트 → 질문 선택으로 복귀.
- 입력창은 여러 줄이며 Enter는 줄바꿈입니다. Ctrl/Cmd+Enter로 전송합니다.
- 점검 결과 아래에 「답변에서 확인되지 않은 첨삭 N건은 뺐어요」를 항상(0건 포함) 표시합니다. 「규칙 밖 첨삭 N건 제외」는 사실과 달라 쓰지 않습니다 (규칙 ID가 스키마 enum이라 규칙 밖 첨삭은 나올 수 없음, UIUX-SPEC §0).

### F12. 화면 언어 (구현)

### 언어 규칙 (2축, 11/03 사용자 확정)
- **목적지 팩**(`pack.language_pair.target`)이 질문·모범답안·스크립트의 언어를 정합니다.
- **모국어 = 화면 언어**(`lang`)가 그 밖의 전부를 정합니다: 화면, 설명, 번역, F3 구조 피드백, F4 첨삭 이유, 스크립트 포인트·분석, 말버릇, 내보내기 안내.
- 발음(`reading`)은 모국어의 문자로 씁니다.

| 목적지 (target) | 모국어 (`lang`) | 질문·스크립트 | 설명·번역 | 발음 표기 |
|---|---|---|---|---|
| 일본 (ja) | ko | 일본어 | 한국어 | 한글 |
| 일본 (ja) | en | 일본어 | 영어 | 로마자 (ヘボン式) |
| 일본 (ja) | ja | 일본어 | 일본어 | 숨김 (번역도 숨김) |
| 한국 (ko, 베타) | ja | 한국어 | 일본어 | 가타카나 |
| 한국 (ko, 베타) | en | 한국어 | 영어 | 개정 로마자 표기 |
| 한국 (ko, 베타) | ko | 한국어 | 한국어 | 숨김 (번역도 숨김) |
| 영미권 (en, 준비 중) | 모두 | 영어 | 모국어 | IPA만 |

- 목적지 언어 = 모국어: `reading`·`translation`을 요청하지도 보여 주지도 않습니다. `points`는 남습니다.
- 열림: 영어 목적지 × 영어 모국어는 "IPA만"과 "같은 언어면 숨김"이 겹칩니다. 기본안은 숨김입니다. 영미권 팩은 준비 중이라 지금은 영향이 없습니다.
- 구현 영향: 스크립트 스키마·프롬프트·`EXPLAIN_LANGS` 발음 게이트가 (target, lang) 쌍 기준으로 바뀝니다. 실호출 확인 1회가 필요합니다 (사용자 승인). `demo-ja.json`은 다시 녹화하지 않고 화면에서 발음·번역을 숨깁니다.

## 6. 비기능 요구사항

- **개인정보**
  - 원문 메일과 첨부는 저장하지 않습니다. 브라우저에는 회사 요약, 질문, 답변과 점검·스크립트 결과만 남고 "끝내기·저장"에서 지웁니다.
  - 서버 로그에는 원문과 첨부 내용을 남기지 않습니다.
  - 입력 단계 마스킹은 구현했습니다 (F1). PDF·이미지 첨부와 문장 중 이름은 가리지 못합니다.
  - Anthropic API의 데이터 보존 설정은 아직 확인하지 않았습니다.
  - 처리방침: `/privacy.html`.
- **입력 방어**: 자료나 답변 안의 지시문은 따르지 않습니다 (프롬프트 규칙). 평가(실호출)에서 메일·답변 속 지시를 따르지 않음을 확인했습니다.
- **접근 제어**: 코드가 설정되지 않으면 모든 요청을 막습니다. 요청 제한은 API별·IP별 10분 단위입니다(접근 확인 20, 질문 생성 10, 점검·스크립트 각 30, 역질문 10, 메일 가입 5). 서버 인스턴스 메모리에 있어 인스턴스 간에 공유되지 않습니다.
- **비용**: 1세션(답변 3건 + 역질문) 약 0.26 USD 실측. Opus 채점 약 0.031 USD/회, Sonnet 약 0.037 USD/회. 테스트는 기본적으로 가짜 클라이언트를 쓰고, 실호출은 프롬프트나 모델을 바꾼 뒤 1회만 합니다.

### 15.5 지금 범위 다음의 로드맵 (11/03)

   - F13(팁 메일)은 코드 변경 없이 사용자의 Resend·Upstash 환경 변수만 남았습니다. 단, Resend 시험 주소(`onboarding@resend.dev`)는 계정 본인에게만 보내지므로 실사용에는 발송 도메인 인증이 필요합니다.

2. **TTS (스크립트 읽어 주기)**: 품질 우선으로 클라우드 TTS를 씁니다. 브라우저 `speechSynthesis`는 비용 0 폴백이며 `localService` 목소리를 먼저 고릅니다(원격 음성은 텍스트가 서버로 감). 클라우드 업체 비교는 `research/TTS-VOICE-EVAL.md`에서 작성 중입니다. 속도 설정은 ⚙ 옵션 패널에 붙입니다.
3. **음성 입력 (STT)**: 전사가 필러(えーと·なんか)를 **그대로** 남겨야 합니다. F4 규칙(예: `del-nanka`)과 F9 말버릇 카운터가 필러를 근거로 하기 때문입니다. 브라우저 `SpeechRecognition`은 필러 유지 여부가 문서화되어 있지 않아 [알 수 없음], 클라우드 STT 비교 뒤 정합니다.
4. **모델 라우팅 A/B**: 비용을 줄이되 품질 기준선 아래로 내려가지 않는지 봅니다.
5. **음성 유료·고급 모델 전환 (제출 후, 결정 11/03)**: 지금은 Gemini API 무료 등급입니다(§15.6). 그래서 녹음(V3·V4)은 꺼 두었습니다(§16-14). 전환하면 `STT_ENABLED=1`과 처리방침 §3을 함께 바꿉니다. 제출 후 유료 등급(유료 등급의 데이터 처리 조건, 더 높은 한도)과 원문을 더 그대로 받아쓰는 STT 모델로 올립니다. 올리면 첫 녹음 때의 무료 등급 안내 한 줄과 TTS 429 쿨다운(`lib/tts.js`)을 다시 판단합니다.
