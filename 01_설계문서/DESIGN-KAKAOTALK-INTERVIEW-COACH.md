# 설계서 A — 카카오톡 면접 코치 (일본 이직 면접 스크립트 코치)

Built with Claude: Japan 2026 제출 후보 A. 작성 2026-10-28. 최종 제출작 결정은 선발 결과(10/30) 후.

## 1. 한 줄 소개
일본에서 이직을 준비하는 한국인·외국인 구직자가, 카카오톡 대화만으로 기업별 면접 질문 연습과 비즈니스 일본어 답변 첨삭을 받는 AI 코치.

## 2. 페르소나와 문제
- 페르소나: 일본 거주 외국인 구직자. 일본어 면접이 부담이고, 에이전트 경유 면접이 반복되며, 기업마다 스크립트를 새로 준비해야 함
- 실제 근거 (개발자 본인 사례): 면접 녹음 전사를 분석해 보니 면접관이 같은 질문을 3번 되물음 — 문제는 일본어 실력이 아니라 "질문에 답하는 구조"였음. 이 경험을 규칙으로 체계화한 자료(business_japanese_corrections_1022.md)가 이미 존재

## 3. 핵심 기능 (MVP)
1. **기업별 질문 생성**: 구인 정보/에이전트 메일 텍스트를 붙여넣으면 해당 기업·포지션 맞춤 예상 질문 10개 생성 (1차/최종, 기술/매니지먼트/역질문 구분)
2. **답변 구조 코칭**: 답변을 4문형으로 점검 — ①復唱(질문 확인) ②結論(첫 문장 결론) ③基準·数字(근거 하나) ④選択肢(상대에게 반환). 어느 단계가 빠졌는지 지적하고 재작성안 제시
3. **비즈니스 일본어 첨삭**: 말버릇 교정 규칙 DB 적용 (아래 5절). 교정 전/후 + 이유를 카톡 메시지로 반환
4. **60초 모범답안**: 질문별 모범답안을 일본어 + 발음 표기 + 한국어 대역 3단 포맷으로 생성, 스크립트 문서로 누적 저장
5. **연습 모드**: 코치가 질문을 하나씩 던지고, 사용자가 답하면 구조·말버릇을 채점하는 모의 면접 루프

확장 (시간 남으면): 음성 답변 전사 분석, 기업별 전회 면담 전제(조직·근무조건 등)를 전제로 깔고 시작하는 연속 면접 모드, 역질문 생성

## 4. 대화 흐름 (카톡)
- 시작: /기업등록 → 구인 텍스트 붙여넣기 → 질문 세트 수신
- 연습: 코치 질문 → 사용자 답변(텍스트) → 즉시 피드백 3종 (구조 점검 / 첨삭 / 모범답안)
- 마감: /스크립트 → 지금까지의 Q&A를 문서로 정리해 반환

## 5. 첨삭 규칙 DB (본인 자료에서 추출한 초기 규칙)
- 삭제 규칙: 〜の形, ちゃんと, なんか, ちょっと(형용사 외), 逆に(역접 아닌 곳), 自分的には
- 치환 규칙: 透過→理解, 集中→承知(맥락별), 資産→コスト/工数/リソース, 〜と思います 연속 사용 시 단정형 전환
- 구조 규칙: 결론 선행, 근거는 숫자 1개만, 반론 대응은 "상대 인정 → 목적 분리 →使い分け" 순서 (반박 금지)
- 규칙은 JSON으로 분리해 면접 중에도 추가·수정 가능하게 설계

## 6. 기술 구성
- 개발: Claude Code. 실행: Claude API (대화·첨삭·채점)
- 프론트: 카카오톡 스타일 채팅 웹 UI (MVP). 실제 카카오톡 채널(카카오 i 오픈빌더/채널 API) 연동은 확장 단계로 분리 — 심사 데모는 웹 채팅으로 전 기능 시연 가능하게
- 데이터: 기업 정보, 질문 세트, 사용자 답변, 스크립트를 세션 단위 JSON 저장. 개인정보(실명·연락처)는 저장 대상에서 제외
- 프롬프트 구조: 역할(코치) + 규칙 DB 주입 + 기업 컨텍스트 + 출력 포맷 고정(피드백 3종 순서)

## 8. 심사 어필 포인트
- 실사용에서 나온 문제 정의 (녹음 전사 실사례)와 이미 검증된 교정 규칙 자산
- "일본어 첨삭"이 아니라 "답변 구조 코칭"이라는 차별점 — 언어 실력과 무관하게 재현 가능
- 일본 이직 시장의 외국인 구직자라는 구체적 페르소나 + 일본 사회의 외국인 노동자 증가 맥락

## 9. 리스크와 대안
- 카톡 채널 실제 연동 심사/승인 지연 가능 → MVP는 웹 채팅 UI로 대체, 채널은 확장 로드맵으로 제시
- 대상이 좁다는 지적 가능 → "외국인 구직자 일반"으로 확장 가능함을 로드맵에 명시 (언어 쌍 교체 구조)
