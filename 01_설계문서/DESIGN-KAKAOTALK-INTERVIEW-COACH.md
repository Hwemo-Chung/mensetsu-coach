# 設計書A — カカオトーク面接コーチ（日本転職面接スクリプトコーチ）

Built with Claude: Japan 2026 提出候補A。作成 2026-10-28。最終提出作の決定は選考結果（10/30）の後。

## 1. 一言紹介
日本での転職を準備する韓国人・外国人の求職者が、カカオトークの会話だけで企業別の面接質問の練習とビジネス日本語の回答添削を受けられるAIコーチ。

## 2. ペルソナと課題
- ペルソナ: 日本在住の外国人求職者。日本語の面接が負担で、エージェント経由の面接が繰り返され、企業ごとにスクリプトを新しく準備しなければならない
- 実際の根拠（開発者本人の事例）: 面接録音の文字起こしを分析したところ、面接官が同じ質問を3回聞き返していた — 問題は日本語力ではなく「質問に答える構成」だった。この経験をルールとして体系化した資料（business_japanese_corrections_1022.md）がすでに存在する

## 3. 中核機能（MVP）
1. **企業別の質問生成**: 求人情報/エージェントメールのテキストを貼り付けると、その企業・ポジションに合わせた想定質問を10問生成（一次/最終、技術/マネジメント/逆質問の区分）
2. **回答構成のコーチング**: 回答を4文型でチェック — ①復唱（質問の確認）②結論（最初の文で結論）③基準・数字（根拠を1つ）④選択肢（相手に返す）。どの段階が欠けているかを指摘し、書き直し案を提示
3. **ビジネス日本語の添削**: 口ぐせの添削ルールDBを適用（下記5節）。添削前/後 + 理由をカカオトークのメッセージで返す
4. **60秒の模範スクリプト**: 質問ごとの模範スクリプトを日本語 + 読み方の表記 + 韓国語の対訳の3段フォーマットで生成し、スクリプト文書として累積保存
5. **練習モード**: コーチが質問を1つずつ投げかけ、ユーザーが答えると構成・口ぐせを採点する模擬面接ループ

拡張（時間が余れば）: 音声回答の文字起こし分析、企業ごとに前回の面談内容（組織・勤務条件など）を前提にして始める連続面接モード、逆質問の生成

## 4. 会話フロー（カカオトーク）
- 開始: /기업등록（企業登録）→ 求人テキストの貼り付け → 質問セットの受信
- 練習: コーチの質問 → ユーザーの回答（テキスト）→ 即時フィードバック3種（構成チェック / 添削 / 模範スクリプト）
- 終了: /스크립트（スクリプト）→ これまでのQ&Aを文書にまとめて返す

## 5. 添削ルールDB（本人の資料から抽出した初期ルール）
- 削除ルール: 〜の形、ちゃんと、なんか、ちょっと（形容詞以外）、逆に（逆接でない箇所）、自分的には
- 置換ルール: 透過→理解、集中→承知（文脈別）、資産→コスト/工数/リソース、〜と思います の連続使用時は断定形に転換
- 構造ルール: 結論を先に、根拠は数字1つだけ、反論への対応は「相手を認める → 目的を分ける → 使い分け」の順（反駁禁止）
- ルールは JSON に分離し、面接期間中にも追加・修正できるように設計

## 6. 技術構成
- 開発: Claude Code。実行: Claude API（会話・添削・採点）
- フロント: カカオトーク風のチャット Web UI（MVP）。実際のカカオトークチャンネル（Kakao i OpenBuilder/チャンネルAPI）との連携は拡張段階に分離 — 審査デモは Web チャットで全機能を実演できるように
- データ: 企業情報、質問セット、ユーザーの回答、スクリプトをセッション単位の JSON で保存。個人情報（実名・連絡先）は保存対象から除外
- プロンプト構成: 役割（コーチ）+ ルールDBの注入 + 企業コンテキスト + 出力フォーマットの固定（フィードバック3種の順序）

## 8. 審査でのアピールポイント
- 作者の過去の面接経験から生まれた課題定義（録音の文字起こしの実例）と、すでに検証済みの添削ルールという資産
- 「日本語の添削」ではなく「回答構成のコーチング」という差別化ポイント — 語学力に関係なく再現可能
- 日本の転職市場における外国人求職者という具体的なペルソナ + 日本社会における外国人労働者の増加という文脈

## 9. リスクと代替案
- カカオトークチャンネルとの実際の連携は、審査/承認が遅れる可能性 → MVPは Web チャットUIで代替し、チャンネルは拡張ロードマップとして提示
- 対象が狭いという指摘の可能性 → 「外国人求職者一般」に拡張できることをロードマップに明記（言語ペアを差し替える構造）
