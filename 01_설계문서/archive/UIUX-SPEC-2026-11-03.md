## 1. 原則

- **シンプル・明快・直感的**（CLAUDE.md）: 最初の画面には、やることが 1 つだけ見えるようにします。子どもでも理解できるラベルを使います。そのため **添削・ノートのトグルボタンは、質問リストが最初に生成されるまで隠します**（`hidden`）。最初の画面（コード入力 + デモボタン）は現状のままです。
- **LINE のようなチャットの見た目を維持します**: 緑のヘッダー、水色の背景（#8cabd8）、左に白い吹き出し（コーチ）、右に緑の吹き出し（自分）。
- **チャットが原本で、パネルはその写しです。** 結果は現状どおり `#log` に吹き出しとして積み上げます。パネル（`#panel`）は同じデータを **描き直します**。DOM ノードは移動しません。理由は 2 つです。モバイルの経路が変わらないこと、そして `test/ui` のセレクタ（`#log > .msg.review` の個数 2、`#log > .msg.script:not(.review):not(.reverse)`、`#log > .msg.reverse`、`#log .q` 10 個）がそのまま通ることです。
- **入力キーは変えません**: Enter は改行、Ctrl/Cmd+Enter は送信です（`app.js:335-337`、`#input` にのみ設定）。ノートの textarea でも Enter は改行で、送信ショートカットはありません。
- **CSP**: `script-src 'self'` と `style-src 'self'` を守ります。インラインスクリプトと HTML の `style=` 属性は使わず、表示・非表示はクラスまたは `hidden` 属性で行います。
- **新しい依存関係やフレームワークは追加しません。** 素の CSS 1 ファイル（`public/style.css`）と既存の ES モジュールだけを使います。

## 2. ブレークポイントとハイブリッド CSS 戦略

| 幅 | レイアウト | 根拠 |
|---|---|---|
| < 1024px（モバイル・タブレット縦） | 現状と同じ 1 列のチャット（最大 560px）。パネルは **全画面オーバーレイ** で開きます。 | test/ui の mobile ビューポートは 390×844 です。 |
| ≥ 1024px（デスクトップ・タブレット横） | パネルを閉じると現状と同じ 560px の 1 列です。パネルを開くと **チャット 560px + パネル 400px = 960px** を中央揃えにします。 | 960px は余白込みで 1024px に収まります。test/ui の desktop ビューポート 1440×900 も含まれます。 |

- **メディアクエリは 1 つだけにします**（`@media (min-width: 1024px)`）。パネルを開いてもチャット列の幅（560px）は変わらないため、吹き出しが折り返し直されることはありません。
- **開閉状態は CSS の `:has()` で読み取ります**: `.app:has(> #panel:not([hidden]))`。JS は `panel.hidden` だけを切り替え、クラスを別途合わせることはしません。（`:has` は Safari 15.4、Chrome 105、Firefox 121 から対応しています [High]。）
- **container query は使いません。** パネル内の吹き出しはすでに `%` 幅（`.msg` 82%、`.script` 92%）で、400px でも折り返されるため不要です。
- **ダークモード（prefers-color-scheme）は今回の範囲から外します。** 現在の画面にダークテーマはなく、11/6 の凍結前に色の検証を増やす理由がありません。代わりに色を `:root` のトークンにまとめておき、後からブロック 1 つで追加できるようにします。
- **390px で横スクロール 0**: `noHorizontalOverflow`（`scrollWidth <= innerWidth`）を 390px と 1440px で通過する必要があります。グリッド列は `minmax(0, 1fr)` とし、パネル内側に `min-width: 0` と `overflow-wrap: anywhere` を指定します。
- **整理**: `.bar` のルールが 3 回定義されているため（`style.css:4, 36, 57`）1 つにまとめます。`.lang { margin-left:auto }` は `.controls select` に上書きされて効いていないルールなので削除します。

CSS の骨格（説明用であり、最終コードではありません）:

```css
:root { --green:#06c755; --green-ink:#047a35; --chat:#8cabd8;
        --page:#e8ecf0; --chat-w:560px; --panel-w:400px; }
.app { max-width:var(--chat-w); height:100dvh; margin:0 auto;
       display:grid; grid-template-columns:minmax(0,1fr);
       grid-template-rows:auto minmax(0,1fr) auto; }
/* モバイル: パネルは全画面オーバーレイ */
.panel { position:fixed; inset:0; z-index:10; background:#fff;
         display:flex; flex-direction:column; min-width:0; }
@media (min-width:1024px) {
  .app:has(> #panel:not([hidden])) {
    max-width:calc(var(--chat-w) + var(--panel-w));
    grid-template-columns:minmax(0,1fr) var(--panel-w); }
  .bar { grid-column:1 / -1; }
  .panel { position:static; grid-column:2; grid-row:2 / 4;
           border-left:1px solid #ddd; overflow-y:auto; }
}
```

- 同じ `<aside id="panel">` 1 つを、CSS だけでオーバーレイに切り替えます。DOM、描画関数、ミラー関数はそれぞれ 1 つです。
- ボトムシートにはドラッグ操作の JS と、半分開いた状態のスクロール処理が必要です。11/6 の凍結前に増やすべきコードではありません。

### (e) 最初の回答 ✗ vs 直した回答 ✓ の比較（デモの核となる場面）

- 同じ `question_id` の **最初の試行と最後の試行** を比較します（レビューのある試行のみ、2 つ以上ある場合）。判定は純粋関数 `compareAttempts(session, qid)`（export.js）が行い、node のテストを付けられます。
- チャットでは、2 回目以降の回答のレビューの後に吹き出し 1 つとして表示されます。クラスは **`msg coach compare`** で、`.review` ではありません（static.test.js:44 が review の個数 2 をアサートしているため）。パネルの添削タブの最上部にも同じ表を描き直します。
- デモでは step ⑤（直した回答 + review）の直後に表示されます。データは `d.steps[0]` と `d.steps[1]` で、録画し直す必要はありません。
- 段階の表（✗/✓）は幅に関係なく同じ 3 列の表です。2 つの回答の原文は **デスクトップ（≥1024px）では横並び、モバイルでは上下** に配置します。

### (g) REL-4 — 再読み込み後のセッション復元

**決定: 黙って復元せず、1 行の通知とボタンを表示します。**

- 保存・復元するのは、質問、試行、メモ、逆質問、`specificity`（F7 の行を描き直すため）、`pack`（KR の段階ラベル）、`version` です。フィールド名の変更（`question_ja`→`question`）より前に保存されたセッションは、`load()` が `version` を見て変換するか破棄します。そうしないと、復元された質問が `undefined` として描画されます。

## 5. アクセシビリティ

**フォーカス順序**（DOM の順序と一致させます）: 行き先 → 画面言語 → `첨삭·노트`（添削・ノート）トグル → `⚙`（(l)） → `끝내기·저장`（終了・保存） → ログ内のインラインボタン → 📎 → 入力欄 → 送信 →（開いていれば）パネルのタブ → パネルの内容。`<aside id="panel">` は `#composer` の後に置きます。

**ARIA**:
- トグル: `<button aria-controls="panel" aria-expanded="false|true">`。ラベルは `data-i18n="panel"`。
- タブ: `role="tablist"` の中に `role="tab"`、`aria-selected`、`aria-controls` を置き、内容は `role="tabpanel"` です。←/→ で移動し、選択されていないタブは `tabindex=-1` です。
- パネル: `<aside aria-label="첨삭·노트">`。`aria-live` は付けません（上記 (c) 参照）。
- モバイルのオーバーレイ: 開くときに `.bar`、`#log`、`#composer` に `inert` を設定します。Esc で閉じます。
- ノートの textarea: `<label>` で「Q3 메모」（Q3 のメモ）を関連付けます。保存状態の文言は `role="status"` です。
- 確認ポップアップ (j)・オプション (l): `<dialog>` + `showModal()`（フォーカスの閉じ込めと Esc はブラウザが処理）。チュートリアルのポップアップ (k) はモーダルではありません。

## 9. 音声出力（TTS）・音声入力（STT） — 承認 2026-11-03

原則: アイコンを 1 つ押すとすぐに動作します。メニュー・再生バー・段階選択は置きません。速度と声は ⚙ オプションにだけ置きます。

```
┌ ③ 모범 스크립트 ────────────────────── [🔊] ┐  ← 押すとすぐ全体を再生、
│ 見積もりがずれたときの判断についてお答えします。│     再生中にもう一度押すと停止(⏹)
│ 私は、残りの工数を基準に、…                   │  ← 読み上げ中の文を強調
│ 발음: 미츠모리가 즈레타 토키노 …              │
│ 번역: 견적이 어긋났을 때의 판단에 대해 …       │
└──────────────────────────────────────────────┘

┌ 入力欄 ───────────────────────────────┬──────┐
│ 답변을 입력하세요                      │ [🎤] │  ← 送信ボタンの上にマイク
│                                       │[보내기]│
└───────────────────────────────────────┴──────┘
  録音中:  [● 0:12  ⏹]  (赤い枠線、最大 90 秒)
```

- 🔊（スクリプトカードの右上）: 押すと、スクリプト全体を 1 回のリクエストで受け取ってストリーミング再生します（無料枠の TTS ≈ 1 分あたり 3 回）。読み上げた部分までを緑・太字で強調します。もう一度押すと止まります。クラウドが失敗した場合は内蔵音声（Kyoko → Google 日本語）で読み上げ、カードの下に「기기 음성으로 읽습니다」（端末の音声で読み上げます）と 1 行表示します。チュートリアル再生中は非表示（AI 呼び出し 0 を維持）。
- 🎤（送信ボタンの上）: 押すとすぐに録音し、もう一度押すと停止してすぐに書き起こします。書き起こし結果は入力欄に入れ、送信ボタンを強調します。すぐに送信しない理由: 認識の誤りがそのまま添削・採点に入ってしまうためです（ユーザーが望めば「書き起こし後すぐ送信」をオプションとして追加）。
- マイク権限の拒否・非対応ブラウザ: 🎤 を薄く表示し、押すと 1 行の案内を出します。
- ⚙ オプション: チュートリアルの説明を表示 / 声（女性 Kore・男性 Charon）/ 読み上げ速度（0.8・1.0・1.2x）。11/03 実装: ストリーミング再生（Web Audio）のため、速度を変えると音の高さも一緒に変わります（⚙ に 1 行の案内）。音の高さの維持（`<audio>`+preservesPitch）は、全体の受信後の再生・CSP `media-src blob:` が必要なため保留。端末音声へのフォールバックは音の高さを維持します。
- アクセシビリティ: 両ボタンとも 44px、aria-label（「스크립트 듣기」（スクリプトを聞く）/「멈추기」（止める）、「음성으로 답하기」（音声で答える）/「녹음 멈추기」（録音を止める））、aria-pressed で状態を表示、録音時間は aria-live。

## 10. 発音の正確さのコーチング — 承認 2026-11-03（"all go tdd"）

目標: 正確な発音。認識器が誤った発音を黙って直してしまわないようにし、認識の精度が落ちたらもう一度話すよう促します。

### 10-1. 回答の音声入力: 認識の精度が落ちたとき
```
(コーチ) 잘 알아듣지 못했어요. 천천히 발음해도 괜찮으니
         한 번 더 말해 보세요.            [🎤 다시 말하기]
```
- 判定（サーバーが `quality: "low"` と理由を一緒に返す）: 書き起こしが空 / 録音の長さに対して文字数が少なすぎる / 認識モデルが聞き取りにくい区間を示した。
- low の場合は入力欄に入れず、上の吹き出しだけを表示します。ok の場合は現状どおり入力欄に入れ、確認後に送信。

### 10-2. 模範スクリプトの音読（新機能）
```
┌ ③ 모범 스크립트 ─────────────────── [🔊] [🎤] ┐
│ 見積もりがずれたときの判断についてお答えします。│
│ 私は、残りの工数を基準に、…                   │
└──────────────────────────────────────────────┘
(コーチ) 따라 읽기 결과 ─ 일치 92%
  見積もりが【ずれた】ときの…   ← 違って聞こえた箇所: 赤い下線
  들린 발음: 「すれた」 → 정답: 「ずれた」
  [🔊 이 부분 듣기]  [🎤 천천히 다시]
```
- 🎤（スクリプトカード）: 押すとすぐに録音し、もう一度押すと停止して書き起こし → スクリプトと **ひらがな単位で比較**（漢字表記の違いは無視） → 違って聞こえた部分を表示。
- 一致率 90% 以上: 「✓ 잘 읽었어요」（✓ よく読めました）。未満: 違う部分だけを指摘し、「천천히 다시」（ゆっくりもう一度）を促す。同じ部分を 🔊 で聞き直せる（その文だけを再生）。
- 比較はコード（文字列のアラインメント）で行い、AI の判断は使いません。書き起こしは原文どおり（verbatim）を要求します。
- チュートリアル再生中は非表示。
