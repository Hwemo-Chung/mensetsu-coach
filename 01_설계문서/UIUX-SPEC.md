## 1. 原則

- **シンプル・明快・直感的**（CLAUDE.md）: 最初の画面には、やることが1つだけ見えます。子どもでも分かるラベルを使います。そのため **添削・ノートのトグルボタンは、質問リストが初めてできるまで隠します**（`hidden`）。最初の画面（コード入力 + デモボタン）は今と同じです。
- **チャットの見た目 — 現在の実装（11/03）**: 白いヘッダー+hairline、白い背景、コーチ/自分ともに左寄せのフラットな行（上に役割ラベル、'나'（自分）ラベルだけ緑）。緑はメインボタン・強調文字・アイコンにのみ使います（#047a35）。
- **チャットが原本で、パネルはその写しです。** 結果は今と同じく `#log` に吹き出しとして積みます。パネル（`#panel`）は同じデータを **描き直します**。DOM ノードは移動しません。理由は2つあります。モバイルの経路が変わらないこと、そして `test/ui` のセレクタ（`#log > .msg.review` の数 2、`#log > .msg.script:not(.review):not(.reverse)`、`#log > .msg.reverse`、`#log .q` 10個）がそのまま通ることです。
- **入力キーは変えません**: Enter は改行、Ctrl/Cmd+Enter は送信です（`app.js:335-337`、`#input` にのみ設定）。ノートの textarea でも Enter は改行で、送信ショートカットはありません。
- **CSP**: `script-src 'self'` と `style-src 'self'` を守ります。インラインスクリプトと HTML の `style=` 属性は使わず、表示・非表示はクラスか `hidden` 属性で切り替えます。
- **新しい依存関係やフレームワークはありません。** 純粋な CSS 1ファイル（`public/style.css`）と既存の ES モジュールのみを使います。

## 2. ブレークポイントとハイブリッド CSS 戦略

| 幅 | レイアウト | 根拠 |
|---|---|---|
| < 1024px（モバイル・タブレット縦） | 1列のチャット（現在の実装 11/03: `.app` に max-width なし、全幅）。パネルは **全画面オーバーレイ** で開きます。 | test/ui の mobile ビューポートは 390×844 です。 |
| ≥ 1024px（デスクトップ・タブレット横） | パネルを閉じると1列です。現在の実装（11/03）: パネルを開くと `grid-template-columns: minmax(420px,2fr) minmax(560px,3fr)`、ガター 24px。行の長さは各ブロックの `max-width: 40em` で制限します。 | test/ui の desktop ビューポート 1440×900 も含まれます。 |

- **メディアクエリ — 現在**: `max-width:1023px`（ヘッダー2行・サブタイトル非表示・picker アイコン非表示、送信 88px）、`min-width:1024px`（横パネル）、`min-width:1280px`（パネル余白のメモ2列）、`prefers-reduced-motion`。チャット列はパネルを開くと 2fr に縮みます。
- **開閉状態は CSS の `:has()` で読み取ります**: `.app:has(> #panel:not([hidden]))`。JS は `panel.hidden` だけを変え、クラスを別途合わせることはしません。（`:has` は Safari 15.4、Chrome 105、Firefox 121 以降で対応しています [High]。）
- **container query は使いません。** パネル内の内容はすでに可変幅（現在: `.msg` width 100%・max-width 40em、`.script` は個別の幅指定なし）で、400px でも折り返されるため不要です。
- **ダークモード（prefers-color-scheme）は今回の範囲から外します。** 今の画面にはダークテーマがなく、11/6 のコードフリーズ前に色の検証を増やす理由がありません。代わりに色を `:root` のトークンにまとめておき、後でブロック1つで追加できるようにします。
- **390px で横スクロール 0**: `noHorizontalOverflow`（`scrollWidth <= innerWidth`）を 390px と 1440px で通過する必要があります。グリッド列は `minmax(0, 1fr)` とし、パネル内側に `min-width: 0` と `overflow-wrap: anywhere` を指定します。
- **整理 — 現在**: `.bar` は1回だけ定義されており（`style.css:19`）、`.lang` に `margin-left:auto` はありません（`style.css:24`）。

### (d) モバイル — パネル（全画面オーバーレイに決定）

**決定: ボトムシートではなく全画面オーバーレイを使います。**

- 同じ `<aside id="panel">` 1つを CSS だけでオーバーレイに切り替えます。DOM、描画関数、ミラー関数はそれぞれ1つです。

### (g) REL-4 — 再読み込み後のセッション復元

**決定: 黙って復元せず、1行の通知とボタンを表示します。**

- 保存・復元するのは、質問、試行、メモ、逆質問、`specificity`（F7 の行を描き直すため）、`pack`（KR のステップラベル）、`version` です。フィールド名の変更（`question_ja`→`question`）より前に保存されたセッションは、`load()` が `version` を見て変換するか破棄します。そうしないと、復元された質問が `undefined` と描画されます。

- 401 でコードを再度尋ねるとき、メモリにすでに session があれば復元しません。質問リストが2回描画されるのを防ぐためです。
- すべての `localStorage.setItem` を try で囲みます（`app.js:211, 247, 294`）。容量超過時に、有料呼び出しの結果が network エラーに変わる問題をなくします。

## 5. アクセシビリティ

**フォーカス順**（DOM の順序と同じにします）: 行き先 → 画面言語 → `첨삭·노트`（添削・ノート）トグル → `⚙`（(l)） → `끝내기·저장`（終了・保存） → ログ内のインラインボタン → 📎 → 入力欄 → 送信 → （開いていれば）パネルのタブ → パネルの内容。`<aside id="panel">` は `#composer` の後に置きます。

- トグル: `<button aria-controls="panel" aria-expanded="false|true">`。ラベルは `data-i18n="panel"`。

ユーザーの指示（11/03）：「現在のフロントエンドを本番水準の画面と比べて改善する。参考は LINE の UI。読みやすく、アマチュアではなく100万ドルの製品水準に」「モバイルは A 案、Web は多くを一度に見られるダッシュボード型」。11/03 午前に採用したフラットな文書型（§0、`research/LAYOUT-BENCHMARK.md`）の読みやすさは残し、LINE の完成度の高い操作パターンを取り入れます。吹き出しだけの LINE 外観（青い背景・両側の吹き出し）には戻しません（長い添削が狭い吹き出しで読みにくくなるため）。

### 11.2 モバイル（1024px 未満）— A 案
- ヘッダーは 1 行（390px で高さ 56px 以下）。マーク＋名前、行き先・言語はアイコン付きの小さな選択、添削・ノート／オプション／終了・保存はアイコンボタン（aria-label 付き）。
- コーチの発言は左に 32px のマーク（アバター）＋本文。自分の発言は右寄せの淡い緑の吹き出し（最大幅 80%、角丸 16px）。
- 長い内容（想定質問・構成チェック・添削・模範スクリプト・比較）は全幅のカード（1px の枠、角丸 12px）。ページの背景は淡いグレーにして、白いカードを浮かせます。
- 想定質問は 1 問 1 枚のカード。カテゴリのチップ＋質問＋根拠＋［練習する］ボタン。タップで選べます（番号の入力も従来どおり使えます）。
- 添削のあとにクイック返信のチップ（まだ練習していない質問 最大 3 つ、逆質問を作る、経歴を入れる）。高さ 44px、横スクロール。
- 入力は 1 本のピル型のバー：［⊕ 添付］［入力欄］［🎤］［送信（丸いアイコン、aria-label「送信」）］。
- マイク・案内の文はバーの上に 1 行だけ表示し、同時に 2 つは出しません。

### 11.3 Web（1280px 以上）— 3 カラムのダッシュボード
- 左（280px）：想定質問のレール。練習済み X/10 の進捗バー、質問ごとの状態（○ 未練習、✗ 足りない要素あり、✓ 質問に答えていてすべての必須要素がある）、カテゴリ。クリックでその質問を練習。いま練習中の質問を強調。独立してスクロール。
- 中央：練習（会話＋入力バー）。
- 右：既存の添削・ノートのパネル（本文 ≤ 40em と余白注釈はそのまま）。
- 質問の生成前は、左のレールに 3 ステップの案内（メールを貼る → 質問を選ぶ → 答える）、右のパネルには選んだ質問と 4文型の説明を出し、空の領域を作りません。
- 1024〜1279px は 2 カラム（会話｜パネル）。レールは出さず、質問は会話の中のカードで選びます。

### 11.4 完了基準（PRD）
1. 390px（ko・en・ja）：ヘッダーが 1 行で高さ 56px 以下。すべての操作に届き、横方向のはみ出しがない。
2. 390px：自分の発言が右寄せ、コーチの発言にマークが付く。想定質問のカードの［練習する］をタップすると、番号を入力したときと同じ流れになる。
3. 390px：入力バーが 1 行で、添付・🎤・送信が 44px 以上のタップ領域を持つ。
4. 1440px・1920px：3 カラム。レールに 10 問と進捗が出て、クリックで練習が始まる。回答後、その質問の状態が ✓ または ✗ に変わる。
5. 1024px：2 カラムでレールなし。
6. すべての文字 14px 以上、コントラスト AA、フォーカスが見える。
7. `npm test`・`npm run test:ui` がすべて通る（意図を変えたテストは理由をテストに書く）。コンソールのエラー 0。
8. ツアー（9 ステップ）とデモ動画の録画スクリプトが新しいレイアウトで動く。

### 11.5 実装メモ（11/03）
- テスト: `test/ui/v3.test.js` が §11.4 の 1〜5 を確認します。意図を変えた既存テスト（`layout.test.js` のフラットな行・送信ボタンの大きさ、`voice.test.js` の 🎤 の位置、`fixes.test.js` のモバイルのヘッダー）には、理由のコメントを付けています。状態（○・✗・✓）の判定は `public/export.js` の `statusOf()` にまとめ、`test/export.test.js` で確認します。
- モバイルのヘッダー: 行き先と言語は、アイコンの上に透明なネイティブの選択を重ねています（タップで端末の一覧が開きます）。選択中の値は 1024px 以上で表示します。
- 案内の行: 録音中のタイマーと初回の案内（端末内で認識）は、入力バーの上の同じ 1 行の枠に並べます。文字起こしのあとは確認の案内だけに切り替わります（`voice-free.test.js` の意図どおり）。

- 質問の生成前は、パネル自体を出しません（トグルは質問ができてから表示する既存の動作）。パネルの「4文型の説明」は、最初の添削が出るまでの空の状態に表示します。
- 会話の列が狭いとき（3 カラムでパネルを開いた 1280〜1440px）は、送信ボタンを丸いアイコンだけにして、入力欄の幅を確保します。
