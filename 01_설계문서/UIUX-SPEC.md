## 0. 이 문서가 바로잡는 전제 3가지

1. **F7 문구 「규칙 밖 첨삭 N건 제외」는 사실과 다릅니다** [높음]. `rule_id`가 스키마 enum이므로(`lib/coach.js:281`) 규칙 DB 밖의 첨삭은 처음부터 나올 수 없습니다. `dropped`가 세는 것은 ①before가 답변에 없음 ②before가 2글자 미만 ③after가 before와 같음 ④after가 대상 언어가 아님(`lib/coach.js:337`)입니다. 그래서 화면 문구는 **「답변에서 확인되지 않은 첨삭 N건은 뺐어요」**로 씁니다.
2. **단계에는 `profile`도 있습니다** [높음]. `code → mail → pick ⇄ answer`에 더해, 경력 한 줄 재생성용 `profile` 단계가 있습니다(`app.js:41, 190, 325`). 상태 전이표(§4)에 넣었습니다.
3. **"노트"의 뜻은 정해지지 않았습니다** [알 수 없음]. 이 문서는 "질문별 자유 메모"라고 가정하고 그립니다. 확정은 §7 열린 결정 1에서 합니다.

## 1. 원칙

- **단순·명료·직관**(CLAUDE.md): 첫 화면에는 할 일이 하나만 보입니다. 아이도 이해할 수 있는 라벨을 씁니다. 그래서 **첨삭·노트 토글 버튼은 질문 목록이 처음 생길 때까지 숨깁니다**(`hidden`). 첫 화면(코드 입력 + 데모 버튼)은 지금과 같습니다.
- **LINE 같은 채팅 모양을 유지합니다**: 녹색 헤더, 하늘색 배경(#8cabd8), 왼쪽 흰 말풍선(코치), 오른쪽 녹색 말풍선(나).
- **채팅이 원본이고 패널은 그 사본입니다.** 결과는 지금처럼 `#log`에 말풍선으로 쌓습니다. 패널(`#panel`)은 같은 데이터를 **다시 그립니다**. DOM 노드를 옮기지 않습니다. 이유는 두 가지입니다. 모바일 경로가 바뀌지 않고, `test/ui`의 선택자(`#log > .msg.review` 개수 2, `#log > .msg.script:not(.review):not(.reverse)`, `#log > .msg.reverse`, `#log .q` 10개)가 그대로 통과합니다.
- **입력 키는 바꾸지 않습니다**: Enter는 줄바꿈, Ctrl/Cmd+Enter는 보내기입니다(`app.js:335-337`, `#input`에만 걸려 있음). 노트 textarea에서도 Enter는 줄바꿈이고 보내기 단축키는 없습니다.
- **CSP**: `script-src 'self'`와 `style-src 'self'`를 지킵니다. 인라인 스크립트와 HTML의 `style=` 속성을 쓰지 않고, 보이기와 숨기기는 클래스나 `hidden` 속성으로 합니다.
- **새 의존성과 프레임워크는 없습니다.** 순수 CSS 한 파일(`public/style.css`)과 기존 ES 모듈만 씁니다.

## 2. 브레이크포인트와 하이브리드 CSS 전략

| 폭 | 레이아웃 | 근거 |
|---|---|---|
| < 1024px (모바일·태블릿 세로) | 지금과 같은 1열 채팅(최대 560px). 패널은 **전체 화면 덮개**로 엽니다. | test/ui의 mobile 뷰포트는 390×844입니다. |
| ≥ 1024px (데스크톱·태블릿 가로) | 패널을 닫으면 지금과 같은 560px 1열입니다. 패널을 열면 **채팅 560px + 패널 400px = 960px**를 가운데 정렬합니다. | 960px는 1024px 안에 여백과 함께 들어갑니다. test/ui의 desktop 뷰포트 1440×900도 포함됩니다. |

- **미디어 쿼리는 하나만 둡니다**(`@media (min-width: 1024px)`). 패널을 열어도 채팅 열의 폭(560px)이 그대로이므로 말풍선이 다시 줄바꿈되지 않습니다.
- **열림 상태는 CSS `:has()`로 읽습니다**: `.app:has(> #panel:not([hidden]))`. JS는 `panel.hidden`만 바꾸고, 클래스를 따로 맞추지 않습니다. (`:has`는 Safari 15.4, Chrome 105, Firefox 121부터 지원합니다 [높음].)
- **container query는 쓰지 않습니다.** 패널 안의 말풍선은 이미 `%` 폭(`.msg` 82%, `.script` 92%)이라 400px에서도 줄바꿈되므로 필요가 없습니다.
- **다크 모드(prefers-color-scheme)는 이번 범위에서 뺍니다.** 지금 화면에 다크 테마가 없고 11/6 동결 전에 색 검수를 늘릴 이유가 없습니다. 대신 색을 `:root` 토큰으로 모아 두어, 나중에 블록 하나로 추가할 수 있게 합니다.
- **390px에서 가로 스크롤 0**: `noHorizontalOverflow`(`scrollWidth <= innerWidth`)를 390px와 1440px에서 통과해야 합니다. 그리드 열은 `minmax(0, 1fr)`로 두고, 패널 안쪽에 `min-width: 0`과 `overflow-wrap: anywhere`를 줍니다.
- **정리**: `.bar` 규칙이 세 번 정의되어 있으므로(`style.css:4, 36, 57`) 하나로 합칩니다. `.lang { margin-left:auto }`는 `.controls select`가 덮어써서 죽은 규칙이므로 지웁니다.

CSS 골격(설명용이며 최종 코드가 아닙니다):

```css
:root { --green:#06c755; --green-ink:#047a35; --chat:#8cabd8;
        --page:#e8ecf0; --chat-w:560px; --panel-w:400px; }
.app { max-width:var(--chat-w); height:100dvh; margin:0 auto;
       display:grid; grid-template-columns:minmax(0,1fr);
       grid-template-rows:auto minmax(0,1fr) auto; }
/* 모바일: 패널은 전체 화면 덮개 */
.panel { position:fixed; inset:0; z-index:10; background:#fff;
         display:flex; flex-direction:column; min-width:0; }
@media (min-width:1024px) {
  .app:has(> #panel:not([hidden])) {
    max-width:calc(var(--chat-w) + var(--panel-w));
    grid-template-columns:minmax(0,1fr) var(--panel-w); }
  .bar { grid-column:1 / -1; }
  .panel { position:static; grid-column:2; grid-row:2 / 4;
           border-left:1px solid #ddd; overflow-y:auto; }
}
```

### (d) 모바일 — 패널 (전체 화면 덮개로 결정)

**결정: 바텀시트 대신 전체 화면 덮개를 씁니다.**

- 같은 `<aside id="panel">` 하나를 CSS만으로 덮개로 바꿉니다. DOM, 렌더 함수, 미러 함수가 하나씩입니다.

### (g) REL-4 — 새로고침 후 세션 복원

**결정: 조용히 복원하지 않고, 한 줄 알림과 버튼을 보여 줍니다.**

- 저장·복원하는 것은 질문, 시도, 메모, 역질문, `specificity`(F7 줄을 다시 그리기 위함), `pack`(KR 단계 라벨), `version`입니다. 필드명 변경(`question_ja`→`question`) 전에 저장된 세션은 `load()`가 `version`을 보고 변환하거나 버립니다. 그러지 않으면 복원된 질문이 `undefined`로 그려집니다.
- 그 밖의 것은 돌아오지 않습니다. `lastMail`은 저장하지 않으므로 "경력 한 줄 입력하고 다시 만들기" 버튼은 다시 나오지 않습니다. 일부만 돌아왔다는 사실을 사용자가 알아야 합니다.
- 복원은 **접근 코드 확인이 성공한 뒤** `onCode` 성공 분기에서 합니다. PRD F11에 따라 페이지를 열 때마다 코드를 먼저 묻습니다.

- 모든 `localStorage.setItem`을 try로 감쌉니다(`app.js:211, 247, 294`). 용량 초과 시 유료 호출 결과가 network 오류로 바뀌는 문제를 없앱니다.

### (j) 언어·목적지 변경 확인 팝업 (승인됨 11/03)

## 5. 접근성

**포커스 순서**(DOM 순서와 같게 둡니다): 목적지 → 화면 언어 → `첨삭·노트` 토글 → `⚙`((l)) → `끝내기·저장` → 로그 안의 인라인 버튼 → 📎 → 입력칸 → 보내기 → (열려 있으면) 패널 탭 → 패널 내용. `<aside id="panel">`는 `#composer` 뒤에 둡니다.

**ARIA**:
- 토글: `<button aria-controls="panel" aria-expanded="false|true">`. 라벨은 `data-i18n="panel"`.
- 탭: `role="tablist"` 안에 `role="tab"`, `aria-selected`, `aria-controls`를 두고, 내용은 `role="tabpanel"`입니다. ←/→로 이동하며, 선택되지 않은 탭은 `tabindex=-1`입니다.
- 패널: `<aside aria-label="첨삭·노트">`. `aria-live`는 달지 않습니다(위 (c) 참조).
- 모바일 덮개: 열 때 `.bar`, `#log`, `#composer`에 `inert`를 겁니다. Esc로 닫습니다.
- 노트 textarea: `<label>`로 「Q3 메모」를 연결합니다. 저장 상태 문구는 `role="status"`입니다.
- 확인 팝업 (j)·옵션 (l): `<dialog>` + `showModal()`(포커스 가두기와 Esc를 브라우저가 처리). 튜토리얼 팝업 (k)는 모달이 아닙니다.

## 6. i18n — 언어 규칙과 새 키 목록

### 6.0 언어 규칙 (2축, 사용자 확정 11/03)

- **축 1 · 목적지 팩**(`pack.language_pair.target`)이 질문·모범답안·스크립트의 언어를 정합니다.
- **축 2 · 모국어 = 화면 언어**(`lang`)가 그 밖의 모든 것을 정합니다: 화면, 설명, 번역, F3 구조 피드백, F4 첨삭 이유, 스크립트 포인트·분석, 말버릇, 내보내기 안내.
- 발음(`reading`)은 모국어의 문자로 씁니다. 억양 기호 ↗↘《》/는 공통입니다.

| 한국 (ko, 베타) | en | 한국어 | 영어 | 개정 로마자 표기 |

- 열린 결정 6: 영어 목적지 + 영어 모국어는 "IPA만"과 "같은 언어면 숨김"이 겹칩니다. 기본안은 같은 언어 규칙 우선(숨김)입니다. 영미권 팩은 준비 중이라 지금 구현에는 영향이 없습니다.

## 7. 열린 결정 (사용자 확인 필요, 각각 기본안 있음)

1. **"노트"의 뜻** — 기본안: **질문별 자유 메모**(textarea, 세션과 함께 localStorage에 저장, .md에 포함, 끝내기 후 삭제). 다른 후보: 모범 스크립트의 억양 포인트 모음, 팩 culture_notes 보기, 말버릇 요약.
2. **패널을 여는 방법** — 기본안: **데스크톱에서 첫 리뷰가 도착하면 한 번 자동으로 첨삭 탭을 열고, 사용자가 닫으면 다시 자동으로 열지 않음**. 모바일은 자동으로 열지 않습니다(덮개가 채팅을 가리므로). 대안: 헤더 토글로만 엽니다.
3. **KR 전환 처리** — 결정 (11/03): **"· 베타" 표시, 역질문(F10) 숨김(당분간 JP 전용), 기록이 있으면 (j) 팝업, 설명 언어·발음은 §6.0**. 이전 기본안(해설 언어 ja만, 저장 후 새로 시작)은 폐기합니다. 참고: KR 팩은 4문형과 모범답안 형식의 근거가 0건이고 원어민 검수가 끝나지 않았습니다(KR-SUMMARY §4-5). 그래서 11/6 전에 열면 JP 경로(공용 코드)를 함께 바꾸는 위험을 감수하게 됩니다. 메뉴에만 열고 실제 생성은 막는 안도 있습니다.
4. **선택 카테고리 「日本で働く理由・在留」를 쓰는 조건** — 기본안: **자료에 재류·외국인 채용·비자·해외 거점 언급이 있을 때만 0~1개**. 대안: 항상 0~1개 허용. 어느 쪽이든 국적이나 출신을 묻는 질문을 막는 culture_notes(jp.json)는 유지합니다. 효과는 실호출 eval로만 확인할 수 있어 별도 승인이 필요합니다.
5. **LINE 녹색의 명암비 수정 범위** — 기본안: **글자가 올라가는 면(헤더, `.me` 말풍선, 보내기, 다음 ▶)만 #047a35(5.47:1)로 진하게 하고, #06c755는 테두리·포커스선·태그 같은 장식에 남김**. 대안: #06c755를 유지하고 그 위 글자를 #111(8.37:1)로 바꿉니다. 이 경우 LINE 느낌은 덜합니다.

6. **영어 목적지 × 영어 모국어의 발음** — 기본안: **같은 언어 규칙 우선(발음·번역 숨김)**. 대안: IPA만 표시. 영미권 팩이 생길 때 정합니다(§6.0).
7. **튜토리얼** — 기본안: **안 A 코치마크 + `1분 둘러보기` 버튼 시작**((k)). 대안: 첫 방문 자동 시작. 안 B(mp4)는 기각.
8. **⚙ 옵션 패널** — 기본안: **튜토리얼 설명 토글 하나로 시작, TTS 속도는 TTS 도입 때 추가**((l)).

## 9. 음성 출력(TTS)·음성 입력(STT) — 승인 2026-11-03

원칙: 아이콘 하나를 누르면 바로 동작합니다. 메뉴·재생 바·단계 선택을 두지 않습니다. 속도와 음성은 ⚙ 옵션에만 둡니다.

```
┌ ③ 모범 스크립트 ────────────────────── [🔊] ┐  ← 누르면 바로 전체 재생,
│ 見積もりがずれたときの判断についてお答えします。│     재생 중 다시 누르면 정지(⏹)
│ 私は、残りの工数を基準に、…                   │  ← 읽는 문장 강조
│ 발음: 미츠모리가 즈레타 토키노 …              │
│ 번역: 견적이 어긋났을 때의 판단에 대해 …       │
└──────────────────────────────────────────────┘

┌ 입력창 ───────────────────────────────┬──────┐
│ 답변을 입력하세요                      │ [🎤] │  ← 보내기 위 마이크
│                                       │[보내기]│
└───────────────────────────────────────┴──────┘
  녹음 중:  [● 0:12  ⏹]  (빨간 테두리, 최대 90초)
```

- 🔊(스크립트 카드 오른쪽 위): 누르면 스크립트 전체를 한 번의 요청으로 받아 스트리밍 재생합니다(무료 등급 TTS ≈ 분당 3회). 읽은 부분까지 초록·굵게 강조합니다. 다시 누르면 멈춥니다. 클라우드 실패 시 내장 음성(Kyoko → Google 日本語)으로 읽고 카드 아래에 "기기 음성으로 읽습니다" 한 줄. 튜토리얼 재생 중에는 숨김(AI 호출 0 유지).
- 🎤(보내기 버튼 위): 누르면 바로 녹음, 다시 누르면 멈추고 바로 전사합니다. 전사 결과는 입력창에 채우고 보내기 버튼을 강조합니다. 바로 보내지 않는 이유: 인식 오류가 그대로 첨삭·채점에 들어가기 때문입니다(사용자가 원하면 "전사 후 바로 보내기"를 옵션으로 추가).
- 마이크 권한 거부·미지원 브라우저: 🎤를 흐리게 두고 누르면 한 줄 안내.
- ⚙ 옵션: 튜토리얼 설명 보기 / 음성(여성 Kore·남성 Charon) / 읽기 속도(0.8·1.0·1.2x). 11/03 구현: 스트리밍 재생(Web Audio)을 위해 속도를 바꾸면 음높이도 함께 바뀝니다(⚙에 한 줄 안내). 음높이 유지(`<audio>`+preservesPitch)는 전체 수신 후 재생·CSP `media-src blob:`이 필요해 보류. 기기 음성 폴백은 음높이를 유지합니다.
- 접근성: 두 버튼 모두 44px, aria-label("스크립트 듣기"/"멈추기", "음성으로 답하기"/"녹음 멈추기"), aria-pressed로 상태 표시, 녹음 시간은 aria-live.

## 10. 발음 정확도 코칭 — 승인 2026-11-03 ("all go tdd")

목표: 정확한 발음. 인식기가 틀린 발음을 조용히 고쳐 주지 않게 하고, 인식이 떨어지면 다시 말하도록 유도합니다.

### 10-1. 답변 음성 입력: 인식이 떨어졌을 때
```
(코치) 잘 알아듣지 못했어요. 천천히 발음해도 괜찮으니
       한 번 더 말해 보세요.            [🎤 다시 말하기]
```
- 판단(서버가 `quality: "low"`와 이유를 함께 돌려줌): 전사가 비었음 / 녹음 길이에 비해 글자가 너무 적음 / 인식 모델이 알아듣기 어려운 구간을 표시함.
- low이면 입력창에 채우지 않고 위 말풍선만 보여 줍니다. ok이면 지금처럼 입력창에 채우고 확인 후 보내기.

### 10-2. 모범 스크립트 따라 읽기 (새 기능)
```
┌ ③ 모범 스크립트 ─────────────────── [🔊] [🎤] ┐
│ 見積もりがずれたときの判断についてお答えします。│
│ 私は、残りの工数を基準に、…                   │
└──────────────────────────────────────────────┘
(코치) 따라 읽기 결과 ─ 일치 92%
  見積もりが【ずれた】ときの…   ← 다르게 들린 곳: 빨간 밑줄
  들린 발음: 「すれた」 → 정답: 「ずれた」
  [🔊 이 부분 듣기]  [🎤 천천히 다시]
```
- 🎤(스크립트 카드): 누르면 바로 녹음, 다시 누르면 멈추고 전사 → 스크립트와 **히라가나 단위로 비교**(한자 표기 차이는 무시) → 다르게 들린 부분을 표시.
- 일치율 90% 이상: "✓ 잘 읽었어요". 미만: 다른 부분만 짚고 "천천히 다시" 유도. 같은 부분을 🔊로 다시 들을 수 있음(그 문장만 재생).
- 비교는 코드(문자열 정렬)로 하며 AI 판단을 쓰지 않습니다. 전사는 원문 그대로(verbatim) 요청합니다.
- 튜토리얼 재생 중에는 숨김.
