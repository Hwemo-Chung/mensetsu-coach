# 公開前の点検

このリポジトリは公開されており、一度プッシュした内容は取り消せません。点検を通らないものは公開しません。「たぶん大丈夫」は未確認として扱います。

## 手順

1. **指示を確かめます。** コミットとプッシュは、同じターンに明示の指示がある場合だけ実行します。「コミット」の指示にプッシュは含まれません。指示がなければ、点検結果の報告で止めます。

2. **対象を確かめます。** `git status --short` で変更を確認し、ステージは `git add <ファイル名>` で個別に行います。`git add -A` は録画や一時ファイルを巻き込むため使いません。

3. **スキャンを実行します。** `scripts/scan.mjs` は `origin` を取得したうえで、未プッシュのコミットの全内容（後のコミットで消したものも含む）とメッセージ、作者、ステージした内容、変更済み・未追跡のファイルを調べます。

   ```bash
   node .claude/skills/publish-check/scripts/scan.mjs
   ```

   | 終了コード・出力 | 意味 | 対応 |
   |---|---|---|
   | 2、`CANNOT CHECK` | 非公開リストや `origin` を読めず確認できない | 中止してユーザーに報告する |
   | 1、`BLOCK` | 個人情報、シークレット、作者の誤り | 公開せず、原因を取り除いて再実行する |
   | 0、`REVIEW` | 文脈次第で問題になる表現、読めないファイル、秘密を含みやすいファイル名 | 該当箇所を読み、判断と理由を報告する |
   | 0、行なし | 検出なし | 次へ進む |

   スクリプトは検出した語や値を表示しません。報告でも値そのものは引用せず、ファイル名とリストの行番号で伝えます。コミット済みの内容で検出された場合は、新しいコミットで消しても履歴に残ります。履歴の修正が必要になるため、ユーザーに判断を求めます。

   空白で分割した語や base64 に変換した値は検出できません。単純な一致による検査であることを前提に、差分も読みます。

4. **テストを実行します。** 実際のリストで個人情報のスキャンも通します。

   ```bash
   PII_DENYLIST=../BuiltWithClaude-2026-private/secrets/.pii-denylist.txt npm test
   ```

   出力の `skipped` が 0 であることを確かめます。このテストは失敗すると検出した語を表示するので、出力を報告に貼りません。画面に関わる変更があれば `npm run test:ui` も実行します。

5. **非公開の公開ルールを確認します。** `../BuiltWithClaude-2026-private/internal-docs/00-current/PUBLISH-RULES.md` を読み、全項目を確認します。プッシュに使うアカウントもここに記載しています。ファイルを読めない場合は中止します。

6. **文書の言語を確認します。** 公開文書とコミットメッセージはビジネス日本語（です・ます調）で書きます。製品データ、フィクスチャ、スナップショットの韓国語（韓国語画面の文言、韓国パックのルール、韓国語の入力例）は翻訳しません。説明文、フォルダ名、ファイル名に韓国語を使いません。

7. **権利と出典を確認します。** `02_ローカル原本/` の内容を持ち込まないこと、外部の素材に出典があることを確かめます。修正を見送る弱点は、README の `実運用前に修正が必要な点` に記載します。

8. **作者を変えません。** リポジトリの `user.name` と `user.email` をそのまま使います。`--author` や環境変数で上書きしません。スキャンは非公開の `.publish-identity.txt` と照合します。

9. **コミットの後、プッシュの直前にもう一度スキャンします。** コミットメッセージと作者はコミットした後でないと検査できません。exit 0 と REVIEW の判断を確かめてからプッシュします。

## 強制の仕組み

スキルは呼び出さなければ動きません。そのためローカルの `.git/hooks/pre-push` からも同じスキャンを実行し、BLOCK と `CANNOT CHECK` ではプッシュを止めます。フックはリポジトリに含まれないので、クローンし直したら作り直します。

```bash
printf '#!/bin/sh\nexec node .claude/skills/publish-check/scripts/scan.mjs\n' > .git/hooks/pre-push && chmod +x .git/hooks/pre-push
```

検査するのは `HEAD` の履歴だけです。`git push --all` や `--tags` は使わず、公開するブランチを指定します。

## 報告の形式

```
## 公開前の点検
- スキャン: exit <コード>（<N> files, <N> commits, BLOCK <N>, REVIEW <N>）
- テスト: pass <N> / fail <N> / skipped <N>
- REVIEW の判断: <ファイルと判断理由、なければ「なし」>
- 公開ルール: <確認した項目と結果>
- 判定: 公開可 / 公開不可（理由）
- 未実施: <省略した確認、なければ「なし」>
```
