# KR-VERIFICATION-LOG — kr パック候補の検証記録

作成 2026-11-02。対象：`KR-K1.md` ~ `KR-K5.md` のパック候補すべて（40件）。成果物：`kr-draft.json`（packs/ 外の草案、未マージ）。要約：`KR-SUMMARY.md`。

## 読み方

- **判定**：検証エージェントによる keep/drop。40件中 keep 22、drop 18。
- **失敗観点**：`none` = 合格。`evidence_fit` = 根拠と文が合っていなかった。`stereotype` = 置換テスト（母語話者・他国籍の応募者にもそのまま当てはまるか）または欠陥前提テストに該当。
- **keep でありながら失敗観点がある候補**（evidence_fit 6件、stereotype 2件）は、候補 payload が**すでに書き直された文案**であり、理由欄は**原案の欠陥**を説明しています。草案には修正後の文案のみが入ります。
- **処理**：パック反映（`kr-draft.json`）／パック反映（一文化）／非注入の参考（パックにスロットなし、このログにのみ記録）／doc_only／棄却。
- このログの作成者は原文を再閲覧していません。原文との照合内容は、検証エージェントの理由を書き写したものです。

## 選択ルール（草案作成前に決定）

1. keep のみ反映します。keep:false は、理由が「一部は使える」であっても反映せず、再提出候補として記録します。
2. スロットに keep 候補がなければ空にしておきます。例外は2つです。`answer_structure` と `model_answer_format` は、作業指示が「JP 4文型の移植」「60秒・韓国語＋日本語話者向け発音＋日本語訳」と内容を直接指定したため、埋めました。この2つはリサーチ根拠ではなくユーザー本人のJPノウハウを移したものであり、韓国語の根拠は0件です（`kr-star` は棄却）。
3. `culture_notes` は1文ずつでなければならないため、複数文からなる K3 候補は、**事実の追加0、検証トークンの欠落0**で、接続語のみを使って1文にまとめました。断片に分けなかった理由：ノートは行単位で個別にプロンプトに入りますが、K4 の検証が主語のないノート（`kr-cn-exception`）をすでに棄却しているためです。原案の文は下記§6にそのまま残し、比較できるようにしました。
4. `daily_questions` は keep の質問18個から10個を選びます。基準：(a) 一般質問は K1 の10個を基本とし、(b) このペルソナにのみ該当する質問（なぜ韓国、在留資格）を入れ、(c) 重複するペアは一つだけ残します。重複するペア：K5 "팀과 의견이 다르면"（チームと意見が異なったら）≈ K1 Q6、K5 "첫 달"（最初の月）≈ K1 Q8、K5 "체류자격과 앞으로 계획"（在留資格と今後の計画）≈ `k3-q-visa-status`。外したもの：K1 Q5（中核的能力、Q4・Q6と範囲が重複）、K1 Q9（希望年収、出典なし）、K5 の重複する3個、K3 の状況型3個（`visa-change`, `workplace-change`, `wh-to-job`：日々の練習より状況への備え用）。検証済みの質問文は修正していません（K5 の質問の해요체（ヘヨ体、非格式の丁寧体）を含む）。
